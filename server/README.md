# Сервер резервных копий

Личный API на Python 3.11+ и SQLite, без сторонних Python-пакетов. Отправляются только завершённые тренировки. Незавершённая сессия остаётся на телефоне. Повторный PUT с тем же ID и содержимым безопасен; другой результат под тем же ID получает 409, серверная запись не перезаписывается. Удаления через API нет.

Сервис подготовлен и проверяется локальными тестами. На реальную VPS он устанавливается отдельно; публикация PWA на GitHub Pages сама по себе сервер не разворачивает.

## Установка с Mac на VPS

Нужны адрес VPS, SSH-пользователь и домен/поддомен, например `backup.твой-домен`. DNS A/AAAA должны указывать на VPS, порты 80/443 — быть доступны. Пароли, SSH-ключи и личный ключ API не отправляй в чат.

На Mac открой **Terminal** и подключись (замени пользователя и адрес):

```sh
ssh пользователь@адрес-vps
```

Далее команды выполняются **на VPS** (Ubuntu 24.04+/Debian 12+). Проверь, что свободен локальный порт 8787. Если занято — сначала выбери другой PORT в конфигурации и соответствующий адрес reverse proxy. Установщик читает фактический PORT из /etc/home-sport.env для проверки готовности.

```sh
sudo apt-get update
sudo apt-get install -y git python3
# Выбери новую папку, чтобы не перезаписать существующий checkout.
git clone https://github.com/pavelmartynovlive-bit/home-sport.git home-sport-backup
cd home-sport-backup
# Просмотри скрипт перед запуском.
less server/install.sh
sudo bash server/install.sh
```

Скрипт создаёт отдельного системного пользователя, копирует сервис в `/opt/home-sport/server`, хранит SQLite в `/var/lib/home-sport`, создаёт случайный личный ключ в `/etc/home-sport.env` с правами 0600 и запускает systemd unit. Повторная установка сохраняет существующий ключ, настройки и базу. Секрет не выводится в журнал и не попадает в репозиторий. Не запускай этот скрипт на Mac: он предназначен для Linux VPS.

## HTTPS

Если на VPS уже есть nginx/Caddy, добавь **отдельный виртуальный хост** с проксированием на `127.0.0.1:8787`. Не заменяй конфигурацию существующих сайтов. CORS для адреса `https://pavelmartynovlive-bit.github.io` обрабатывает API; не добавляй `Access-Control-Allow-Origin: *`.

Для новой VPS можно установить Caddy по официальным инструкциям https://caddyserver.com/docs/install. Шаблон — `server/Caddyfile.example`. Замени домен. Добавь этот отдельный site block в существующий Caddyfile или подключи отдельный файл через `import`, затем проверь полную конфигурацию:

```sh
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Для nginx нужны действующий TLS-сертификат и `proxy_pass http://127.0.0.1:8787;` в location виртуального хоста. Используй `client_max_body_size 128k`, `proxy_read_timeout 20s`. Если у тебя уже работает nginx, не устанавливай рядом Caddy на занятые 80/443. Не отключай проверку TLS в браузере.

Проверка после настройки, без ключа:

```sh
curl --fail https://ТВОЙ-ДОМЕН/health
```

Ожидается `{"ok": true}`. Для private endpoints нужны `Authorization: Bearer ...`; сервер не публикует историю без ключа. `/health` не содержит данных тренировок.

## Подключение телефона

Открой PWA → **Резервная копия**. Введи HTTPS-адрес и значение `BACKUP_TOKEN` из `/etc/home-sport.env` (просмотри его локально на VPS через `sudo nano /etc/home-sport.env`, затем выйди без изменений). Не присылай содержимое файла или снимок с ключом в чат.

При подключении сначала проверяется ключ. Потом копируется существующая история и новые завершённые тренировки. Ключ сохраняется в localStorage телефона, а не в публичном JavaScript. На сервере он находится в env-файле. Имеющий этот ключ может читать/добавлять копии; при утечке сгенерируй новый ключ, поменяй его на VPS, перезапусти службу и переподключи телефон. Адрес и ключ сохрани в менеджере паролей: после переустановки телефона они нужны для восстановления.

Статус «Копия на сервере сохранена» появляется после подтверждения записи в SQLite. При отказе сети/сервера/ключа история остаётся локальной и ожидает отправки. Повторные попытки идут при открытии, возвращении в приложение, появлении сети и раз в минуту, пока приложение открыто. Закрытое PWA на iPhone не гарантирует отправку в фоне.

**Восстановить историю с сервера** добавляет отсутствующие тренировки, не удаляет локальные и не меняет активную сессию. При конфликте ID локальная версия сохраняется; автоматической синхронизации редактирования нет. Кнопка «Отключить» удаляет только подключение на телефоне, не историю и не серверную базу.

При открытии подключённого приложения история также проверяется и восстанавливается автоматически. Подтверждения отправки сверяются с текущей базой сервера: если запись пропала после восстановления VPS из старого снимка, она снова отправится с телефона. Конфликт одной записи не блокирует отправку остальных.

## Резервная копия самой VPS

SQLite использует WAL: копировать только живой `.sqlite3` через `cp` недостаточно. Используй SQLite backup API:

```sh
sudo python3 /opt/home-sport/server/backup.py \
  /var/lib/home-sport/sessions.sqlite3 \
  /var/backups/home-sport/history-$(date -u +%Y%m%d-%H%M%S).sqlite3
```

Полученный файл нужно регулярно копировать **за пределы этой VPS**, например существующей системой резервного копирования в защищённое внешнее хранилище. Конкретное место ещё нужно выбрать; файловая копия на той же VPS не защищает от потери сервера. Имя назначения должно быть новым; скрипт проверяет целостность и не перезаписывает существующий файл.

Для восстановления серверной базы останови `home-sport`, сохрани текущую базу **вместе с WAL/SHM**, положи проверенный snapshot в `/var/lib/home-sport/sessions.sqlite3`, выставь владельца `home-sport:home-sport` и права 0600, убери старые WAL/SHM только после сохранения их в архив и запусти службу. Сначала проверь восстановление на отдельной тестовой копии. Если snapshot старее последних отправленных тренировок, открой обновлённую подключённую PWA: оставшиеся на телефоне записи отправятся снова при проверке истории. Активная база сервера не заменяется через приложение.

## Проверки

```sh
python3 -m unittest server.test_server -v
npm test
VITE_BASE_PATH=/home-sport/ npm run build
VITE_BASE_PATH=/home-sport/ npm run test:e2e
```

Проверяются авторизация, CORS, повторная отправка, конфликт ID, валидация, сохранность после перезапуска, целостный SQLite snapshot, локальная очередь, повторная отправка, восстановление после очистки хранилища. Browser-тест запускает временный API на 127.0.0.1:8788 с отдельной тестовой базой; настоящие данные и ключи не используются.

## Ограничения

Один личный ключ, без аккаунтов и регистрации. До 10 000 тренировок; одна запись до 128 KiB. API не кэшируется service worker. База содержит результаты открытым текстом на VPS; доступ к VPS и внешним snapshot нужно защищать. Клиент разрешает HTTP только для localhost в разработке, production — HTTPS. Не открывай Python-порт в Интернет: используй обратный прокси и оставляй HOST=127.0.0.1.
