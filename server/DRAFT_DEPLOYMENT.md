# Обновление VPS: копия текущей тренировки

Клиент и API реализованы и проверены в облаке. Реальная VPS ещё не обновлена: SSH-доступа из облачного окружения нет, пользователь сейчас с телефона. Не выдавай публикацию PWA за установку серверной функции.

## Задача для локальной сессии Codex на Mac

Прочитай этот файл и `server/DEPLOYMENT.md`, обнови существующий API Home Sport на VPS. Пользователь уже разрешил эту функцию и её развёртывание. Используй доступную SSH-конфигурацию Mac, не проси пароли/ключи в чат, не выводи содержимое `/etc/home-sport.env`, `phone-connection.txt` или `server-recovery.env`.

Сервер: `132.243.23.229`, HTTPS `https://home-sport.132-243-23-229.sslip.io`. API: `/opt/home-sport/server/server.py`, systemd `home-sport`, loopback порт 8789. SSH-пользователя здесь нет: определи по существующей конфигурации либо уточни только имя пользователя. Не меняй nginx, TLS, VPN, другие сайты, ключ, путь базы или расписание резервных копий.

1. Получи последние изменения `main`, сохраняя локальные пользовательские изменения. Прочитай `server/upgrade-drafts.sh`, проверь текущий API, unit и доступность резервной копии. Этот Linux-скрипт **не запускается на Mac**.
2. Доставь актуальные `server.py`, `backup.py` и `upgrade-drafts.sh` в закрытый временный каталог на VPS. Запусти `sudo bash <путь>/upgrade-drafts.sh`. Скрипт проверяет существующую службу, делает согласованный SQLite snapshot и сохраняет старый код, обновляет только `server.py`, перезапускает API и проверяет локальный health. При ошибке после установки откатывает код; базу не заменяет.
3. Убедись, что публичный `/health` возвращает `ok: true` и `draft: true`. Проверь GET `/v1/draft` с текущим ключом, полученным локально без вывода секрета: версия 1, целочисленная revision и session null либо незавершённая тренировка. Без ключа/с неверным ключом должен быть 401; CORS — только origin GitHub Pages.
4. Не записывай фиктивную тренировку в реальный `/v1/draft`: это единственная текущая сессия пользователя. Серверные проверки записи, гонок, завершения, снимка и миграции запускай с отдельной временной тестовой базой: `python3 -m unittest server.test_server -v` (9 тестов).
5. Проверь, что существующий `home-sport-snapshot.timer` включён, свежий snapshot содержит таблицы sessions и draft и проходит integrity_check. На Mac проверь LaunchAgent `ru.home-sport.backup`, скачивание нового снимка и его целостность. Полная SQLite-копия включает черновик автоматически: расписания и скрипты менять не нужно.
6. После успешного развёртывания обнови `server/DEPLOYMENT.md` фактическими результатами, без ключей и личных тренировок. Отдельно укажи проверку телефона: пользователь должен отметить подход, подождать 3 секунды и увидеть «Текущая тренировка сохранена на сервере». Для этого не удаляй настоящую историю/хранилище телефона.

## Поведение

- Локальная запись остаётся мгновенной после каждого изменения.
- После 3 секунд без новых правок отправляется текущая тренировка. При ошибке связь проверяется при открытии, возвращении в PWA, online и раз в минуту, пока приложение видно.
- Закрытый iPhone PWA может остановить выполнение: закрытие раньше отправки сохраняет правки локально, серверная копия догонит при возвращении.
- GET/PUT `/v1/draft` используют bearer auth и тот же CORS. PUT проверяет ожидаемую revision, не заменяет чужую текущую сессию и не принимает завершённую тренировку.
- Завершение через существующий PUT `/v1/sessions/:id` в одной транзакции сохраняет историю и очищает соответствующий draft. Запоздалый PUT черновика не воскресит завершённую сессию.
- При восстановлении черновика текущая локальная сессия не перезаписывается. Незнакомое изменение на сервере показывает конфликт, сохраняя обе копии. Потеря ответа, новые правки после неё и восстановление старого snapshot проверены.
- Со старым API резервные копии завершённых тренировок продолжают работать, а PWA явно сообщает, что для текущей сессии надо обновить сервер.
