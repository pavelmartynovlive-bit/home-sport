# Домашняя тренировка

Личное mobile-first PWA: одна программа из 30 упражнений и пяти блоков: мобилити и растяжка с общими отметками, 22 подхода в остальных блоках. Без регистрации. Работает локально; можно подключить личную VPS для автоматических резервных копий.

## Запуск

Нужен Node.js 22.12+ (в облачном окружении проверен Node.js 24).

```sh
npm ci
npm run dev
```

Для проверки полной PWA/offline-функциональности запускай production-сборку:

```sh
npm run build
npm run preview -- --port 4173
```

Service worker включён в production-сборке. Vite dev-сервер предназначен для разработки и не кэшируется.

## Использование

На главной — запуск/продолжение тренировки и переход к истории. Блоки последней тренировки и обзора программы убраны.

- В блоках «Корпус + мобилити» и «Растяжка» есть только список упражнений, техника и одна галочка на весь раздел. Повторения, секунды и подходы в этих блоках не вводятся. Общая отметка сохраняется после перезагрузки; в истории отображается статус блока. Старые сессии сохраняются без потери данных.
- Начни тренировку, меняй вес и повторения каждого подхода, отмечай выполненное кнопкой ✓.
- Нажми заголовок карточки для режима фокусировки. «Следующее упражнение» не отмечает пропущенные подходы автоматически.
- Для упражнений «на сторону» отметь подход после выполнения обеих сторон; введённое значение относится к каждой стороне. Для круговых движений коленом — к каждому направлению каждой ноги.
- Для молотков значение 24 означает 8 + 8 + 8; его можно изменить по фактическому результату.
- Можно сохранить частичную тренировку. Пропущенные подходы отмечаются в истории; следующая тренировка подставляет последние **выполненные** значения каждого подхода или значения программы.
- Незавершённая сессия сохраняется после каждого изменения. После перезагрузки выбирай «Продолжить тренировку».
- На экране завершения и в деталях тренировки из истории есть иконка «Скопировать результаты». В буфер попадает текст с датой, длительностью, статусами блоков и фактическими значениями подходов. Его можно вставить в сообщение. При запрете доступа к буферу доступно ручное выделение и копирование.
- Время тренировки — время с начала до сохранения, включая время закрытого приложения.

## Резервная копия на VPS

На главной и в истории есть «Резервная копия»: подключение HTTPS-адреса и личного ключа, статус отправки, восстановление. Сначала проверь и установи API по [инструкции сервера](server/README.md). Сам GitHub Pages принимает только статические файлы, не копии тренировок.

При сохранении завершённой тренировки данные сначала записываются на телефон, затем отправляются на VPS. При ошибке остаются в очереди и повторяются при следующем открытии/возвращении в приложение/появлении сети или раз в минуту, пока PWA открыто. Нельзя рассчитывать на отправку из закрытого PWA на iPhone. Восстановление добавляет записи по ID, не стирает локальную историю и не меняет активную сессию. Повторная отправка не создаёт дубли.

Ключ вводится на телефоне, не вшивается в публичную сборку. После удаления данных сайта для восстановления снова нужны адрес и ключ: сохрани их в менеджере паролей. На VPS нужно отдельно настроить HTTPS и резервные копии базы за пределы сервера. Пока сервер не подключён, результаты остаются только на телефоне.

## iPhone и офлайн

Размести содержимое `dist/` на статическом хостинге с HTTPS. Открой сайт в Safari → «Поделиться» → «На экран Домой». После первого успешного открытия и установки service worker интерфейс доступен без интернета. На телефоне HTTP по локальной сети не подходит для service worker; localhost разрешён только на самом устройстве.

Результаты хранятся в localStorage под ключом `home-sport:v1` на этом устройстве и для этого origin. Перенос на другой адрес, очистка данных сайта или удаление браузерного хранилища не переносит/сохраняет историю. При ошибке записи приложение показывает предупреждение; завершение не закрывает сессию, пока запись не удалась. Приватный режим может ограничивать хранение.

## Техника

Для каждого упражнения есть 2–4 подсказки. Готовые GIF пока не приложены: вместо них отображается placeholder. Добавляй GIF в `public/exercises/<exercise-id>.gif` (идентификаторы в `src/program.ts`). Для видео можно изменить `techniqueMedia` на путь к локальному MP4 — проигрыватель поддерживает `playsInline`. Медиа входят в офлайн-кэш после повторной сборки. Workbox по умолчанию ограничивает размер одного кэшируемого файла 2 MiB: используй небольшие клипы. Любые предупреждения об исключённом файле нужно устранить перед публикацией.

## Проверки

```sh
python3 -m unittest server.test_server -v  # 5 тестов API/SQLite
npm test                 # 15 тестов модели, хранения, экспорта и backup-клиента
npm run build           # TypeScript + Vite + manifest и service worker
npm run test:e2e         # 9 браузерных сценариев на production-сборке
```

Playwright использует установленный `/usr/bin/chromium`. Для другой машины укажи `CHROMIUM_PATH=/путь/к/chromium`, либо установи Chromium и настрой путь в `playwright.config.ts`. Браузерные сценарии проверяют полную тренировку, восстановление сессии, технику, историю, подстановку отдельных весов, офлайн-перезагрузку, запись офлайн, частичное завершение, ошибку хранилища и ширину 320px, общие отметки мобилити и растяжки, её сохранение, снятие и отображение в истории. Safari на физическом iPhone в облаке не проверялся.

## Структура

- `src/program.ts` — персональная программа и подсказки.
- `src/types.ts` — Workout, WorkoutExercise, ExerciseSet, WorkoutSession, CompletedSet.
- `src/store.ts` — проверка данных, сохранение, подстановка результатов.
- `src/export.ts` — формат результатов для сообщения.
- `src/CopyResults.tsx` — копирование и ручное выделение при недоступном буфере обмена.
- `src/backup.ts`, `src/useBackup.ts`, `src/BackupPanel.tsx` — подключение, очередь, подтверждения и восстановление.
- `server/` — API Python/SQLite, systemd service, установщик и проверка серверных копий.
- `src/App.tsx` — главная, список, фокус, техника, завершение, история.
- `src/style.css` — адаптивный интерфейс, без внешних шрифтов.
- `vite.config.ts` — PWA и офлайн-кэш.

Для новых облачных задач используй существующий checkout `/workspace/home-sport`; отдельный worktree не нужен.

## GitHub Pages

Публикация настроена через `.github/workflows/pages.yml`: push в `main` запускает тесты, сборку и загрузку на GitHub Pages. В настройках репозитория **Settings → Pages → Source** должен быть выбран **GitHub Actions**. Если включение Pages выполнено после первого push, повторно запусти workflow **Publish PWA to GitHub Pages** во вкладке Actions.

Адрес после успешной публикации: https://pavelmartynovlive-bit.github.io/home-sport/

Локальная проверка сборки по пути GitHub Pages:

```sh
VITE_BASE_PATH=/home-sport/ npm run build
VITE_BASE_PATH=/home-sport/ npm run test:e2e
```

Manifest, service worker, иконки и медиа используют тот же базовый путь. Обычная сборка без `VITE_BASE_PATH` остаётся доступна в корне сайта.
